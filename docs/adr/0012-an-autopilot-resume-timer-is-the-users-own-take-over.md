# An autopilot resume timer is the user's own take-over

When autopilot pauses on a low allowance it schedules its own resume where the host has a scheduler (elsewhere the report gives the resume command), and the timer acts as the user's `--take-over`: the user's request for the resume, recorded on the run card, is its authorization, so the run needs no new invocation. The timer runs `--take-over --timed`, which resumes only a card that still ended `paused-allowance` with its timer set and otherwise reports the state and changes nothing, and a pause or any take-over cancels it. We chose this over leaving the resume to the user and over an operating-system timer, because the user asked for the run to continue by itself through each runtime's own scheduler, and a timer that resumed blindly could hand back a run the user had paused.
